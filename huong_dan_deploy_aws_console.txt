BƯỚC 1: TẠO MẠNG VPC KHÔNG TỐN TIỀN (LOẠI BỎ HOÀN TOÀN NAT GATEWAY)
================================================================================

1.1. Thao tác trên AWS Console:
1. Đăng nhập https://console.aws.amazon.com/ -> Chọn Region `ap-southeast-1 (Singapore)`.
2. Tìm dịch vụ `VPC` -> Bấm nút cam **Create VPC**.
3. Tại mục **Resources to create**: Chọn **VPC only** (Không chọn VPC and more để tránh bị AWS tự nhét NAT Gateway tính tiền).
   - **Name tag**: `cgv-free-vpc`.
   - **IPv4 CIDR block**: `10.0.0.0/16`.
   - Bấm **Create VPC**.
4. Vào menu bên trái chọn **Internet Gateways** -> Bấm **Create internet gateway**:
   - Tên: `cgv-free-igw` -> Bấm **Create**.
   - Bấm **Actions** -> Chọn **Attach to VPC** -> Chọn `cgv-free-vpc`.
5. Vào menu **Subnets** -> Bấm **Create subnet**:
   - Chọn VPC: `cgv-free-vpc`.
   - **Subnet 1 (Public Subnet A)**: Name: `cgv-public-1a`, AZ: `ap-southeast-1a`, CIDR: `10.0.1.0/24`.
   - Bấm **Add new subnet**:
   - **Subnet 2 (Public Subnet B)**: Name: `cgv-public-1b`, AZ: `ap-southeast-1b`, CIDR: `10.0.2.0/24`.
   - Bấm **Create subnet**.
   - Chọn cả 2 subnet vừa tạo -> Bấm **Actions** -> **Edit subnet settings** -> Tích chọn: **Enable auto-assign public IPv4 address** -> Bấm **Save**.
6. Vào menu **Route Tables** -> Chọn Route Table chính của VPC:
   - Chọn tab **Routes** -> Bấm **Edit routes** -> Bấm **Add route**:
     + Destination: `0.0.0.0/0`
     + Target: Chọn `Internet Gateway` (`cgv-free-igw`).
   - Bấm **Save changes**.

1.2. Tạo Security Groups:
Vào **Security Groups** -> Bấm **Create security group**:
- **SG 1: `cgv-ec2-sg` (Dành cho 2 máy ảo EC2)**:
  + Inbound Rules:
    * SSH (Port 22) -> Source: `My IP` (Chỉ IP nhà/công ty bạn được remote vào).
    * Custom TCP (Port 8000 - Kong Gateway) -> Source: `0.0.0.0/0` (Mở cho web/app gọi API).
    * All traffic (Tất cả cổng) -> Source: Chọn chính nó `cgv-ec2-sg` (Cho phép 2 con EC2 giao tiếp với nhau qua IP nội bộ).
- **SG 2: `cgv-db-sg` (Dành cho RDS PostgreSQL & Redis)**:
  + Inbound Rules:
    * PostgreSQL (Port 5432) -> Source: `cgv-ec2-sg`.
    * Custom TCP (Port 6379) -> Source: `cgv-ec2-sg`.

GIẢI THÍCH VÌ SAO & MỤC ĐÍCH:

  + Mục đích: Tiết kiệm chi phí. NAT Gateway tốn tối thiểu 32$/tháng dù bạn không dùng gì. Bằng cách

BƯỚC 5: THIẾT LẬP SWAP MEMORY (RAM ẢO) ĐỂ CHỐNG TRÀN BỘ NHỚ TRÊN CẢ 2 EC2
================================================================================

ĐÂY LÀ BÍ KÍP QUAN TRỌNG NHẤT CỦA DEVOPS ĐỂ CHẠY JAVA TRÊN EC2 FREE TIER!
Vì EC2 chỉ có 1GB RAM thật, ta sẽ trích 2GB từ ổ cứng SSD để làm RAM ảo (Swap).
Khi các ứng dụng Java chạy lên, phần bộ nhớ ít dùng sẽ được đẩy sang SSD, giúp máy ảo
sở hữu tổng cộng 3GB RAM (1GB thật + 2GB ảo), không bao giờ bị đứng máy hay văng lỗi OOM!

Thực hiện trên CẢ 2 MÁY ẢO EC2:

1. Mở Terminal máy cá nhân, SSH vào máy ảo:
   chmod 400 cgv-keypair.pem
   ssh -i cgv-keypair.pem ubuntu@<PUBLIC_IP_CUA_EC2>

2. Chạy lần lượt các lệnh sau trên terminal của EC2:
```bash
# 1. Tạo file swap 2GB
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 2. Cấu hình tự động nạp Swap khi khởi động lại máy
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 3. Tinh chỉnh độ ưu tiên dùng RAM thật (chỉ dùng Swap khi RAM thật còn < 15%)
sudo sysctl vm.swappiness=15
echo 'vm.swappiness=15' | sudo tee -a /etc/sysctl.conf

# 4. Kiểm tra thành quả
free -h
```
-> Kết quả hiện ra: `Mem: 960Mi`, `Swap: 2.0Gi` -> Máy ảo của bạn giờ đã có sức mạnh tương đương gói 3GB RAM!

BƯỚC 6: TRIỂN KHAI KAFKA & KONG GATEWAY TRÊN MÁY ẢO 1 (`cgv-ec2-infra`)
================================================================================

1. SSH vào máy 1 (`cgv-ec2-infra`):
   ssh -i cgv-keypair.pem ubuntu@<IP_MAY_1>

2. Cài đặt Docker & Docker Compose:
```bash
sudo apt update && sudo apt install -y docker.io docker-compose
sudo usermod -aG docker ubuntu
newgrp docker
```

3. Tạo file `docker-compose.yml` để chạy Kafka (chế độ KRaft không cần Zookeeper để tiết kiệm RAM) và Kong Gateway:
```bash
cat << 'EOF' > docker-compose.yml
version: '3.8'
services:
  # Apache Kafka KRaft (Siêu nhẹ, chỉ ăn ~250MB RAM)
  kafka:
    image: bashj79/kafka-kraft:latest
    container_name: cgv-kafka
    ports:
      - "9092:9092"
    environment:
      KAFKA_ENABLE_KRAFT: "yes"
      KAFKA_CFG_NODE_ID: 1
      KAFKA_CFG_PROCESS_ROLES: "broker,controller"
      KAFKA_CFG_CONTROLLER_QUORUM_VOTERS: "1@localhost:9093"
      KAFKA_CFG_LISTENERS: "PLAINTEXT://0.0.0.0:9092,CONTROLLER://0.0.0.0:9093"
      KAFKA_CFG_ADVERTISED_LISTENERS: "PLAINTEXT://10.0.1.X:9092" # <-- Thay bằng PRIVATE IP của Máy 1!
      KAFKA_CFG_LISTENER_SECURITY_PROTOCOL_MAP: "CONTROLLER:PLAINTEXT,PLAINTEXT:PLAINTEXT"
      KAFKA_CFG_CONTROLLER_LISTENER_NAMES: "CONTROLLER"
      KAFKA_HEAP_OPTS: "-Xmx256m -Xms128m" # Giới hạn RAM cho Kafka
    restart: always

  # Kong API Gateway
  kong:
    image: kong:3.6
    container_name: cgv-kong
    ports:
      - "8000:8000" # Cổng nhận request từ ngoài Internet
      - "8001:8001" # Cổng Admin nội bộ
    environment:
      KONG_DATABASE: "off" # Chạy dbless bằng file declarative để không tốn RAM
      KONG_DECLARATIVE_CONFIG: /etc/kong/kong.yml
      KONG_PROXY_ACCESS_LOG: /dev/stdout
      KONG_ADMIN_ACCESS_LOG: /dev/stdout
      KONG_PROXY_ERROR_LOG: /dev/stderr
      KONG_ADMIN_ERROR_LOG: /dev/stderr
      KONG_ADMIN_LISTEN: 0.0.0.0:8001
    volumes:
      - ./kong.yml:/etc/kong/kong.yml
    restart: always
EOF
```

4. Tạo file cấu hình định tuyến `kong.yml`:
File này chuyển tiếp request từ cổng 8000 sang Private IP của Máy 2 (nơi chạy 4 microservices):
```bash
cat << 'EOF' > kong.yml
_format_version: "3.0"
services:
  - name: booking-service
    url: http://10.0.1.Y:8082 # <-- Thay bằng PRIVATE IP của Máy 2!
    routes:
      - name: booking-route
        paths:
          - /api/v1/bookings

  - name: catalog-service
    url: http://10.0.1.Y:8083 # <-- Thay bằng PRIVATE IP của Máy 2!
    routes:
      - name: catalog-route
        paths:
          - /api/v1/movies
          - /api/v1/cinemas
          - /api/v1/showtimes

  - name: identity-service
    url: http://10.0.1.Y:8081 # <-- Thay bằng PRIVATE IP của Máy 2!
    routes:
      - name: identity-route
        paths:
          - /api/v1/auth
          - /api/v1/users

  - name: payment-service
    url: http://10.0.1.Y:8085 # <-- Thay bằng PRIVATE IP của Máy 2!
    routes:
      - name: payment-route
        paths:
          - /api/v1/payments
EOF
```

5. Khởi động Máy 1:
   docker-compose up -d

GIẢI THÍCH VÌ SAO & MỤC ĐÍCH:
- Vì sao dùng Kafka KRaft thay vì Kafka + Zookeeper truyền thống?
  + Mục đích: Tiết kiệm tối đa bộ nhớ. Bản Kafka cũ cần 1 cụm Zookeeper chạy song song tốn thêm
    500MB RAM. Chuẩn KRaft mới loại bỏ hoàn toàn Zookeeper, giúp Kafka chạy êm ái chỉ với 256MB RAM.
- Vì sao dùng Kong DB-less mode (`KONG_DATABASE: "off"`)?
  + Mục đích: Kong thông thường cần 1 database PostgreSQL riêng để lưu cấu hình route. Chế độ
    DB-less đọc trực tiếp từ file `kong.yml`, khởi động trong 1 giây và tiết kiệm 100% dung lượng DB.

GIẢI THÍCH VÌ SAO & MỤC ĐÍCH:
- Vì sao cấu hình `-XX:+UseSerialGC`?
  + Mục đích: Tiết kiệm CPU và RAM tối đa. Mặc định Java dùng G1GC tiêu tốn thêm 50-100MB RAM
    chỉ để quản lý bộ nhớ dọn rác. SerialGC cực kỳ gọn nhẹ, phù hợp hoàn hảo cho các container
    chạy trên máy ảo 1 vCPU và RAM nhỏ của gói Free Tier.
- Vì sao các container giao tiếp qua Private IP `10.0.1.X` thay vì Public IP?
  + Mục đích: Miễn phí tiền mạng và tăng tốc độ. Lưu lượng truyền tải giữa các máy ảo trong cùng
    VPC qua Private IP được AWS miễn phí hoàn toàn (0$), và độ trễ chỉ dưới 0.5 mili-giây.

BƯỚC 8: DEPLOY REACT FRONTEND LÊN S3 + CLOUDFRONT CDN (MIỄN PHÍ)
================================================================================

8.1. Cấu hình biến môi trường API cho Frontend:
Trên máy tính cá nhân, mở file `.env` hoặc cấu hình API trong React:
VITE_API_BASE_URL=http://<PUBLIC_IP_MAY_1>:8000
(Trỏ thẳng vào cổng Kong Gateway của Máy ảo 1).

8.2. Build và đẩy lên S3:
1. Chạy lệnh build:
   npm run build
2. Vào AWS Console -> Dịch vụ `S3` -> Tạo Bucket `cgv-fe-free-storage`.
   - Tích chọn: **Block all public access** (Bảo mật).
   - Bấm **Create bucket**.
3. Mở bucket vừa tạo -> Bấm **Upload** -> Kéo toàn bộ file trong thư mục `dist/` thả vào -> Bấm **Upload**.

8.3. Tạo CloudFront CDN:
1. Dịch vụ `CloudFront` -> Bấm **Create distribution**:
   - Origin domain: Chọn bucket `cgv-fe-free-storage`.
   - Origin access: Chọn **Origin access control settings (recommended)** -> Bấm **Create new OAC**.
   - Default root object: `index.html`.
2. Bấm **Create distribution**.
3. Bấm vào nút vàng **Copy policy** do CloudFront gợi ý -> Vào S3 Bucket -> Tab **Permissions** -> Dán vào ô **Bucket policy** để cấp quyền cho CloudFront đọc file.
4. Tại CloudFront, vào tab **Error pages** -> Tạo 2 rule chuyển hướng lỗi:
   - Rule 1: HTTP Error `403` -> Response page: `/index.html` -> Code: `200: OK`.
   - Rule 2: HTTP Error `404` -> Response page: `/index.html` -> Code: `200: OK`.
5. Đợi 3 phút -> Copy link CloudFront (Ví dụ: `https://d3xxxx.cloudfront.net`).

GIẢI THÍCH VÌ SAO & MỤC ĐÍCH:
- Mục đích: CloudFront nằm trong gói Always Free (Miễn phí 1TB băng thông/tháng). Không cần thuê
  máy chủ chạy web tĩnh, người dùng truy cập web với tốc độ cực nhanh và bạn không mất 1 đồng nào.

BƯỚC 10: TRIỂN KHAI BẰNG KUBERNETES (K8S) TRÊN EC2 FREE TIER VỚI K3S (MIỄN PHÍ)
================================================================================

10.1. Vì sao chọn K3s thay vì Kubeadm / EKS cho Free Tier?
- AWS EKS tính phí ~73$/tháng cho cụm Control Plane (Không hề có Free Tier).
- Kubeadm nguyên bản cần tối thiểu 2 vCPU và 2GB RAM cho riêng Master Node.
- K3s (bởi Rancher/CNCF): Là bản phân phối Kubernetes chính thức siêu nhẹ, toàn bộ
  Control Plane đóng gói trong 1 file binary duy nhất chỉ tốn ~50MB RAM! Chạy hoàn hảo
  trên EC2 `t2.micro`/`t3.micro` (1GB RAM + 2GB Swap) mà vẫn hỗ trợ 100% chuẩn K8s
  (Pods, Services, Ingress, HPA, ConfigMaps, Secrets).

10.2. Cài đặt K3s trên EC2 (Chỉ 1 câu lệnh duy nhất):
SSH vào máy ảo EC2 và chạy lệnh cài K3s:
```bash
# Cài đặt K3s (bỏ qua traefik mặc định để dùng Kong API Gateway)
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="--disable traefik" sh -

# Cấp quyền cho user ubuntu dùng lệnh kubectl không cần sudo
sudo chmod 644 /etc/rancher/k3s/k3s.yaml
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
echo 'export KUBECONFIG=/etc/rancher/k3s/k3s.yaml' >> ~/.bashrc

# Kiểm tra node K8s đã sẵn sàng:
kubectl get nodes
```
-> Kết quả hiện: `STATUS: Ready`! Bạn đã có một cụm Kubernetes Production hoàn chỉnh trên AWS 0 đồng!

10.3. Triển khai toàn bộ hệ thống bằng thư mục `k8s/`:
Clone source code CGV về EC2 và thực thi theo đúng thứ tự:
```bash
# 1. Tạo Namespace cách ly
kubectl apply -f k8s/00-namespace.yml

# 2. Tạo Cấu hình & Mật khẩu
kubectl apply -f k8s/01-configmap.yml
kubectl apply -f k8s/02-secrets.yml

# 3. Khởi động Kong Gateway
kubectl apply -f k8s/kong/

# 4. Triển khai các Microservices
kubectl apply -f k8s/services/identity-service/
kubectl apply -f k8s/services/catalog-service/
kubectl apply -f k8s/services/booking-service/
kubectl apply -f k8s/services/payment-service/

# 5. Mở Ingress đón khách
kubectl apply -f k8s/ingress/ingress.yml

# 6. Kiểm tra toàn bộ Pods đang chạy
kubectl get pods -n cgv-prod -o wide
```

10.4. Giải thích vì sao & Mục đích của việc dùng K8s K3s trên Free Tier:
- Mục đích: Trải nghiệm và làm chủ quy trình DevOps / Kubernetes thực tế của doanh nghiệp
  ngay trên nền tảng AWS với chi phí 0 ĐỒNG.
- Khi cần chuyển sang môi trường Production của tập đoàn lớn (AWS EKS hay Google GKE),
  toàn bộ các file `.yml` trong thư mục `k8s/` này sẽ được giữ nguyên 100% mà không
  cần sửa đổi bất kỳ dòng code nào!
